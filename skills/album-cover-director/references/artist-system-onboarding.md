# Artist system onboarding and maintenance

`artist-system.md` is optional. It is a living, artist-local brief, not a form
the user must know how to write before making a cover.

## When it is missing

For an ongoing artist workspace, create the template from
`assets/artist-system-template.md`. Then draft its first version from the
available evidence: artist description, lyrics, audio, release titles,
rights-cleared identity references, reference images, and the user's stated
avoid list. Mark unsupported claims as working hypotheses.

Do not block a first cover because information is absent. Proceed from the
title and available evidence, then offer a concise first-draft artist system
for the user to correct. Ask only for information that can materially change
continuity: a recurring identity, a hard avoid, or whether any current visual
trait must persist across releases.

## When it already exists

Read the existing system before creating directions. Preserve its explicit
constraints. Compare it with artist-local feedback and learned preferences:

- a one-release correction remains in that release's feedback record;
- a repeated observation becomes `learned-preferences.md` first;
- update `artist-system.md` only when the user explicitly identifies the rule
  as artist-wide, or when repeated evidence makes it a stable continuity rule.

Make additions or narrow revisions with a short change-log entry naming the
local feedback release slugs and the boundary. Do not silently rewrite or
remove a user-authored rule. If new evidence conflicts with an existing hard
constraint, preserve the constraint and report the conflict instead of
averaging them.

## Initial interview, when useful

Use the smallest useful set of prompts, and accept natural-language answers:

1. What should make a listener recognise this artist across releases?
2. Which visual or title behaviors are already overused or forbidden?
3. Is there a recurring person, character, object, or point of view?
4. What should vary radically from song to song?

Any answer may be `unknown`. The system remains revisable through feedback.
